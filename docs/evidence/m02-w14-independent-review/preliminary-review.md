## Actionable findings

1. **P1: held native-option approval survives changed option meaning before the physical write.** `apps/extension/src/drivers/choice-drivers.ts:59-83` and `:127-147` match only the option value digest/enabled state. Actual W09 initially approves Country=United States for opaque value `17`; changing that option's label to Canada yields fresh W09 `PAUSE_FOR_CONFIRMATION` / `NO_SEMANTIC_MATCH`, but the held transaction performs one `SELECT_VALUE` mutation and returns `VERIFIED`, with readiness `READY`. Literal value `US` relabelled `Select a country` reproduces the same issue while fresh W09 refuses the placeholder. Reproduction: `independent-native.spec.ts`, before-write cases. Raw: `native-before-write-opaque-canada.json`, `native-before-write-us-placeholder.json`. Require current approved option semantics, including label and disabled evidence, at the action boundary; a value digest alone is insufficient.

2. **P1: option-preservation fallback reports READY after the selected option's meaning changes.** `apps/extension/src/dynamic-engine.ts:125-133` removes all option evidence from fallback binding; `:1351-1395` then accepts value-only observations from `choice-drivers.ts:149-153`. After an actual `VERIFIED` Country=17/United States fill, relabelling the selected option Canada leaves reconciliation `READY`, although fresh W09 refuses the current field. The US/placeholder variation also remains READY. Native mutation count stays one, proving no replacement fill accounts for the result. Reproduction: native after-verified cases. Raw: `native-after-verified-opaque-canada.json`, `native-after-verified-us-placeholder.json`. Preserve unchanged selected-option semantics while allowing unrelated unselected option-window changes. The append-unselected Mexico positive control passes with `READY` and no additional mutation (`native-append-positive.json`).

3. **P2: undo can publish VERIFIED after ownership or validation becomes stale.** `apps/extension/src/driver-engine.ts:1392-1437` builds unconditional COMPLETE from value/acceptance and awaits result hashes without execute's settled-description and final publication fences. Actual text execution starts with Prior/Your contact and writes Synthetic. An undo input handler changes the description to Employer while restoring Prior; the undo returns `VERIFIED`, while fresh W09 returns `BLOCK_UNSUPPORTED`. A second independent case pauses the exact UNDO idempotency/result hash after settlement, changes `aria-invalid` to true, and releases it: undo still returns `VERIFIED`. Native witnesses show two mutations total, one execute and one undo, in each case. Raw: `native-undo-ownership.json`, `native-undo-last-hash.json`. Apply ownership/currentness and current site-acceptance publication requirements consistently to undo.

4. **P2: public-contact summary omits controls appearing only in the final DOM inventory.** `e2e/extension/public-contact/run-contact.ts:327-357` derives changes solely from the initial inventory, and `:473-501` can therefore report full precision and zero unknown/nonpositive changes despite new final controls. A lightweight exact-source replay with initial empty First Name, followed by First Name=Synthetic plus a newly inserted nonpositive Social Security Number=Synthetic, reports precision 1, unmeasurable controls 0 and unexpected nonpositive changes 0. Account for the union of initial and final literal identities, including topology completeness. A final-only control has unknown initial/causal state; this finding does not assert that its value was written by the extension or that any retained public run exhibited the case.
